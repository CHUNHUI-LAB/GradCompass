# GradCompass

从研究生申请路径出发，查找机器人与具身智能导师、研究机会、官方截止日期与材料要求。

## 专业简介试点候选范围

- 新增 5 位导师的职业概况、实验室及公开资源、2–3 项代表成果和参考说明；不推断设备分配、剩余名额、资助或指导风格
- 46 条独立机会，涉及 30 位导师：MSc 2、MPhil 21、PhD 21、RA 2
- 同一导师的不同学位或不同 RA 岗位分开显示、筛选与比较；两条 RA 均为郑湃的独立公开职位，不能计为两位导师
- 本科起点、无需强制推免、无需已有硕士是学位路径的默认收录条件，不再提供可关闭的资格复选框
- RA 为受雇科研岗位，须单独有官方本科任职条件与当前招募证据；学位招生条件不能替代岗位学历要求
- 33 条原始路径记录中，未知或排除项保留证据，但不进入默认机会列表
- 12 条学位/批次日期记录与 2 条独立 RA 截止记录，2 项已核实材料要求
- 证据核验日为 2026-10-01；每日检查已启用，首轮执行尚待验证

官方项目门槛不是个人资格判断。学位等值、成绩、英语、毕业时间、导师意向，以及岗位技能、工作许可和名额，仍需按个人与具体项目核实。

## 静态运行与托管

无需构建或客户端依赖。用静态 HTTP 服务器打开本目录，例如 `python -m http.server 4173`。ES 模块及 JSON 读取需要 HTTP，不建议直接双击 HTML。

所有资源使用相对路径，支持 GitHub Pages 仓库子路径；`.nojekyll` 避免 Jekyll 改写。本次专业简介试点为独立本地候选，尚未发布；基于已发布提交 `267e820b3f11a1d081380630da499e7cb84284da`。

## 数据与状态

- `data/advisor-profiles.json`：5 位现有导师的公开职业与实验室简介，按原 advisorId 关联；其余 27 人保持原内容并显示待补充。简介与学位资格、招募及 RA 任职判断分离
- `data/catalog.json`：原三个经审阅批次的学位与导师证据；R2 未改动其内容或核验日期
- `data/ra-positions.json`：仅两条经官方全文核实的在招 RA 岗位；不包含历史岗位或泛化招募队列
- `data/update-status.json`：独立调度状态，明确区分“检查已启用”和“首轮成功运行”
- `data/catalog-test-manifest.json`：原规范化数据的 21 项检查

界面的中文短述只改善阅读，不修改源证据或补造名额。RA 截止时刻未公布的保留为 null；未来日期不保证仍有名额。

## 检查

- `npm test`：49 项 Node 单元与 DOM 合约渲染测试，无需额外依赖
- `node tests/browser-smoke.mjs`：可选实际浏览器测试，需环境提供 Playwright 与 Chromium；`TEST_URL` 指向待验站点，`QA_OUTPUT` 指定报告目录
- `python scripts/freeze.py`：按明确的 21 文件白名单生成 `release-manifest.json`

本次 5 人专业简介候选尚未进行实际浏览器、桌面或手机截图验收。49 项 Node/DOM 合约测试不代表视觉、焦点和完整无障碍验证通过；旧版本结果不适用于本次候选。详见 `QA.md`。
